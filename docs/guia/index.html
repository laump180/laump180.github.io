    CAPÍTULO 1

    Qué construimos

    Laura es desarrolladora de videojuegos y necesitaba un portfolio: una página web donde mostrar quién es y qué ha hecho, como una hoja de vida pero más visual.

    La página tiene:

    • Inicio, con una ilustración grande, su nombre y un minijuego que se juega con el teclado: una encapuchada recoge cristales brillantes.
    • Proyectos: tarjetas con los juegos que hizo y una página de detalle para cada uno.
    • Sobre mí: su experiencia, sus estudios y un botón para descargar su CV.
    • Contacto: un formulario para escribirle.
    • Música de fondo con un control de volumen.

    Antes de escribir una sola línea de código, nos dieron tres cosas:

    1. Un mockup: una imagen de cómo debía verse la página terminada. Es como el plano de una casa antes de construirla.
    2. Los assets: las imágenes ya recortadas (la ilustración, el personaje, los cristales, los íconos).
    3. Los tokens: la lista de colores y letras que usa el diseño, con nombres. Por ejemplo, wine-500 es el rojo vino.
    En simple

    Nuestro trabajo fue convertir un dibujo (el mockup) en una página de verdad que funciona en el computador y en el celular.

    CAPÍTULO 2

    Las ideas básicas de una web

    Toda página web está hecha de tres ingredientes. Piensa en una persona:

    IngredienteQué haceComparación
    HTMLDice qué hay en la página: un título, un párrafo, una imagen, un botón.El esqueleto
    CSSDice cómo se ve: colores, tamaños, posición, letras.La ropa y el maquillaje
    JavaScriptDice qué pasa cuando haces algo: hacer clic, escribir, mover el personaje.Los músculos

    Sobre esos tres ingredientes usamos herramientas que hacen el trabajo más fácil y ordenado:

    HerramientaPara qué la usamos
    ReactConstruir la página con piezas reutilizables llamadas componentes. Lo vemos en el capítulo 3.
    TypeScriptEs JavaScript con "etiquetas" que dicen qué tipo de dato es cada cosa. Así el editor te avisa de errores antes de abrir la página.
    Tailwind CSSEscribir el CSS con nombres cortos directamente en el HTML, como text-red-500 o p-4.
    ViteEl "horno": junta todos los archivos, los prepara y muestra la página mientras trabajas. Cada vez que guardas, se actualiza sola.
    React RouterHace que la página tenga varias secciones con su propia dirección (/proyectos, /contacto) sin recargar todo.
    En simple

    HTML, CSS y JavaScript son los ladrillos. React, TypeScript, Tailwind y Vite son las herramientas del albañil: no son obligatorias, pero hacen el trabajo más rápido y con menos errores.

    CAPÍTULO 3

    Componentes: piezas de Lego

    La idea más importante de React es el componente. Un componente es una pieza de la página que puedes usar muchas veces, como una pieza de Lego.

    Mira el mockup: hay botones rojos en el inicio, en los proyectos y en el juego. En lugar de escribir el mismo botón muchas veces, lo escribimos una vez como componente y lo usamos donde haga falta.

    Así se ve un componente muy simplificado:

    Un componente sencillo
    function Saludo({ nombre }) {
  return <p>Hola, {nombre}</p>
}

// Y así se usa, dos veces:
<Saludo nombre="Laura" />
<Saludo nombre="Ana" />
    • function Saludo(...)Creamos una pieza llamada Saludo. Los componentes siempre empiezan con mayúscula.
    • { nombre }Lo que va entre llaves son las props: los datos que le pasas a la pieza. Es como decirle "este saludo es para Laura".
    • return <p>...Lo que la pieza dibuja en la pantalla. Parece HTML, pero está dentro de JavaScript (eso se llama JSX).
    • {nombre}Las llaves dentro del HTML significan "pon aquí el valor de esta variable".
    • <Saludo nombre="Laura" />Usamos la pieza como si fuera una etiqueta HTML más. En pantalla aparece "Hola, Laura".

    Toda la página de Laura está hecha así: piezas pequeñas (un botón, un rombo decorativo, una tarjeta) que se juntan en piezas más grandes (la sección de proyectos), que a su vez forman la página entera.

    Por qué

    Si mañana Laura quiere los botones más redondos, se cambia un solo archivo y cambian todos los botones del sitio a la vez.

    CAPÍTULO 4

    Instalar Node y crear el proyecto

    Node es un programa que permite usar JavaScript fuera del navegador. Lo necesitamos porque todas las herramientas (Vite, React Router…) funcionan con él. Junto con Node viene npm, una "tienda de piezas" de donde se descargan librerías.

    El computador tenía una versión vieja de Node (la 16). Las herramientas modernas necesitan una nueva. Para cambiarla usamos nvm, que permite tener varias versiones instaladas y elegir cuál usar:

    Terminal
    nvm install 26.13.0   # descarga la versión 26
nvm use 26.13.0       # y la deja activa
node -v               # comprueba: debe decir v26.13.0
    En simple

    La terminal es la ventana negra donde escribes órdenes al computador. Lo que va después de # es un comentario: una nota para personas que el computador ignora.

    Luego creamos el proyecto con Vite. Un solo comando genera la carpeta con todo lo básico:

    Terminal
    npm create vite@latest mi-portfolio -- --template react-ts
cd mi-portfolio
npm install      # descarga las piezas que el proyecto necesita
npm run dev      # enciende la página en http://localhost:5173

    Después instalamos las piezas extra: React Router (para las páginas), Tailwind (para los estilos) y dos librerías de íconos.

    Qué salió mal

    La primera vez, con la versión 22.19 de Node, npm instaló en silencio una versión vieja de React Router. ¿Por qué? Porque la versión nueva pide Node 22.22 o más. Moraleja: si una librería no se instala en la versión que esperas, revisa qué versión de Node pide.

    CAPÍTULO 5

    Ordenar las carpetas

    Un proyecto desordenado es como una casa donde los zapatos están en la nevera. Elegimos una forma de ordenar llamada Screaming Architecture ("arquitectura que grita"): las carpetas se nombran por lo que hace la página, no por cuestiones técnicas.

    Carpeta src/ (el código)
    app/                 ← el arranque: rutas, estilos generales
features/            ← cada parte de la página en su propia carpeta
  hero/              ← la sección grande del inicio
  echo-collector/    ← el minijuego
  projects/          ← los proyectos
  about/             ← "Sobre mí"
  contact/           ← el formulario
  ambient-audio/     ← la música
  home/              ← junta hero + juego + proyectos
  not-found/         ← la página de error 404
shared/              ← lo que usan varias partes
  ui/                ← botones, rombos, marcos…
  layout/            ← barra de arriba y pie de página
  assets/            ← imágenes

    Abres features y entiendes al momento de qué trata el proyecto: tiene un juego, proyectos, contacto… Por eso "grita".

    Tres reglas de convivencia

    1. Cada carpeta de features tiene un archivo index.ts que funciona como la puerta de entrada: dice qué se puede usar desde fuera.
    2. Una parte nunca entra por la ventana de otra: solo usa lo que la otra ofrece por su puerta.
    3. Lo que necesitan varias partes (como el botón) vive en shared, el "cuarto común".
    En simple

    Es como un edificio de apartamentos: cada apartamento tiene su puerta, nadie entra por la ventana del vecino, y la escalera y el ascensor son de todos.

    CAPÍTULO 6

    Colores y letras con nombre

    El diseño se llama "Ceniza y Burdeos": negros, grises y un rojo vino. En lugar de escribir el código del color (#8E2A2E) cada vez, le dimos nombre a cada color en un solo lugar:

    src/app/styles/index.css
    @theme {
  --color-ash-950: #0a0a0a;    /* el fondo casi negro   */
  --color-bone-100: #f1e9dd;   /* el blanco hueso       */
  --color-wine-500: #8e2a2e;   /* el rojo vino          */
  --font-display: 'Cormorant Garamond', serif;  /* letra de títulos */
}
    • @theme { ... }Le decimos a Tailwind: "estos son los colores y letras de nuestro diseño".
    • --color-wine-500: #8e2a2eEl rojo vino se llama wine-500. El número indica qué tan oscuro es.

    Gracias a esto podemos escribir en cualquier parte text-wine-500 (texto rojo vino) o bg-ash-950 (fondo casi negro), y Tailwind sabe qué color es.

    Cómo se lee una clase de Tailwind

    ClaseSignifica
    text-bone-100Texto de color blanco hueso
    bg-wine-900Fondo (background) vino oscuro
    p-4Relleno interior (padding) de 4 unidades por todos los lados
    mt-8Margen arriba (margin-top) de 8 unidades
    border border-ash-800Un borde fino de color gris
    lg:text-7xlLetra enorme, pero solo en pantallas grandes
    Por qué

    Si un día el rojo cambia, se cambia en una línea y toda la página se actualiza. Y como los colores tienen nombres, el código se lee casi como una frase.

    CAPÍTULO 7

    Las direcciones de la página

    Cada página tiene su dirección, como las habitaciones de una casa. Las definimos en una lista:

    DirecciónQué muestra
    /Inicio: ilustración, juego y proyectos destacados
    /proyectosTodos los proyectos
    /proyectos/echoesEl detalle de un proyecto (cambia la última palabra)
    /sobre-miExperiencia, estudios y CV
    /contactoFormulario
    cualquier otraPágina "Un eco perdido" (error 404)
    src/app/router/routes.tsx (resumido)
    {
  path: 'proyectos/:slug',
  lazy: async () => ({ Component: (await import('@/features/projects')).ProjectDetailPage }),
}
    • path: 'proyectos/:slug'La dirección. Los dos puntos significan "aquí va algo que cambia". slug es el nombre corto del proyecto, por ejemplo echoes.
    • lazy: async () => ...Lazy significa "perezoso": el código de esa página solo se descarga cuando alguien la visita.
    • await import(...)"Espera a traer este archivo". Mientras no visites Contacto, tu navegador no descarga el código de Contacto.

    Todas las páginas comparten un marco: la barra de arriba y el pie de página. Lo que cambia es solo el centro.

    CAPÍTULO 8

    La barra de arriba

    Qué ves: "Laura Muñoz Pérez." con el punto en rojo, los enlaces Proyectos · Sobre mí · Contacto separados por rombitos, y un adorno a la derecha. La barra se queda pegada arriba cuando bajas.

    Cómo está hecha:

    • Pegada arriba: la clase sticky top-0. Sticky significa "pegajoso": el elemento se pega al borde cuando lo alcanzas al bajar.
    • El enlace activo se subraya: usamos NavLink, un enlace especial de React Router que sabe si estás en su página y nos deja cambiarle el estilo.
    • En el celular los enlaces no caben, así que se esconden y aparece un botón de menú (☰). Al tocarlo se abre la lista; al cambiar de página se cierra solo.
    Cómo se marca el enlace activo
    <NavLink to="/proyectos"
  className={({ isActive }) => isActive ? 'text-bone-100' : 'text-ash-300'}>
  Proyectos
</NavLink>
    • to="/proyectos"A dónde lleva el enlace.
    • isActive ? A : BEsto se lee "¿estoy en esta página? Si sí, usa A; si no, usa B". El signo ? es una pregunta corta.
    Qué salió mal

    La primera versión cerraba el menú del celular con una orden "cuando cambie la página, ciérrate". La herramienta de revisión de código (el linter) nos avisó de que eso hace trabajar de más a la página. La solución fue más inteligente: el menú recuerda en qué página se abrió; si estás en otra, está cerrado. Sin órdenes extra.

    La ilustración que se funde con el fondo

    La imagen de las ruinas está a la derecha y se va volviendo negra hacia la izquierda, hasta mezclarse con el fondo. No editamos la imagen: le pusimos una máscara.

    En simple

    Una máscara es como mirar la foto a través de un vidrio pintado con degradado: donde el vidrio es negro ves la foto, donde es transparente la foto desaparece.

    La máscara (CSS)
    mask-image: linear-gradient(to right, transparent, black 22%);
    • linear-gradient(to right, ...)Un degradado que va de izquierda a derecha.
    • transparent, black 22%Empieza invisible y a partir del 22 % del ancho la foto ya se ve completa.

    Primero el celular

    En el celular no hay espacio para texto e imagen lado a lado, así que la imagen va arriba y se funde hacia abajo. Escribimos los estilos pensando primero en la pantalla pequeña, y luego agregamos lg: para cambiar lo necesario en pantallas grandes. A esto se le llama mobile-first.

    Animación al bajar

    Cada sección aparece con un suave movimiento hacia arriba cuando llega a la pantalla. Lo hace un componente llamado Reveal que "vigila" si la sección ya está visible, usando una herramienta del navegador llamada IntersectionObserver (literalmente, "observador de cruces").

    CAPÍTULO 10

    Proyectos: datos y tarjetas

    Aquí aprendimos una lección muy útil: separar la información de la forma de mostrarla.

    Los datos de los proyectos (título, descripción, imágenes) viven en un archivo aparte, como una ficha:

    src/features/projects/data/projects.ts (resumido)
    export const PROJECTS = [
  {
    slug: 'echoes',
    title: 'Echoes',
    tags: ['Unity', 'C#', 'UI Toolkit', 'Audio'],
    description: 'Un juego de suspenso narrativo en 2D...',
    image: { src: echoesMenu, alt: 'Menú principal de Echoes...' },
  },
  // ...y aquí el siguiente proyecto
]
    • [ ... ]Los corchetes son una lista. Cada proyecto es un elemento.
    • { slug: ..., title: ... }Las llaves son una ficha (un objeto) con campos que tienen nombre y valor.
    • alt: '...'La descripción de la imagen para quien no puede verla (por ejemplo, personas ciegas que usan un lector de pantalla).

    Y el componente de la lista solo recorre esas fichas y dibuja una tarjeta por cada una:

    ProjectGrid.tsx (resumido)
    {PROJECTS.map((project) => (
  <ProjectCard key={project.slug} project={project} />
))}
    • PROJECTS.map(...)Map significa "para cada elemento de la lista, haz esto". Aquí: "para cada proyecto, dibuja una tarjeta".
    • key={project.slug}Una etiqueta única para que React sepa cuál tarjeta es cuál si la lista cambia.
    Por qué

    Para agregar un proyecto nuevo, Laura solo tiene que añadir una ficha más al archivo de datos. No toca ningún diseño. La tarjeta y la página de detalle aparecen solas.

    La tarjeta y el detalle

    • Tarjeta: imagen a la izquierda, título, etiquetas separadas por rayitas, descripción y botón "Ver proyecto". En el celular, todo en una columna.
    • Detalle: etiquetas como "Game Jam · 48 h", la descripción, un recuadro "Mi aporte" que explica qué hizo Laura dentro del equipo, una sección desplegable con más información, un botón para jugar en Unity Play y una galería de capturas.
    • Portada con logo: si un proyecto no tiene una imagen buena para la portada, la ficha puede decir image: { logo: 'unity' } y se muestra el logo de Unity.
    Qué salió mal

    Cuando un proyecto tenía una sola captura, se veía enorme porque ocupaba todo el ancho. Lo arreglamos dejando siempre dos columnas: una sola imagen ocupa la mitad.

    CAPÍTULO 11

    Sobre mí y el CV descargable

    Laura nos pasó su hoja de vida en PDF y la convertimos en datos, igual que los proyectos: una lista de experiencias, otra de estudios y otra de habilidades.

    • Línea de tiempo: cada trabajo o estudio es un punto en una línea vertical. El que está en curso lleva un destello que brilla.
    • Habilidades agrupadas en cuatro columnas: Videojuegos, Web, Herramientas e Idiomas.
    • Botón "Descargar CV".

    Cómo se hace un botón de descarga

    Pusimos el PDF en la carpeta public/. Todo lo que hay ahí se copia tal cual a la página publicada, así que el archivo queda en una dirección fija. Luego un enlace con el atributo download:

    Enlace de descarga (HTML)
    <a href="/cv/Laura-Munoz-Perez-CV.pdf" download>Descargar CV</a>
    • href="/cv/..."Dónde está el archivo.
    • downloadLe dice al navegador "descárgalo" en lugar de abrirlo.
    Privacidad

    No pusimos el teléfono de Laura en la página para evitar spam. Pero ojo: el PDF sí lo incluye. Cuando subas un documento a internet, revisa qué datos personales lleva.

    CAPÍTULO 12

    Contacto y la página de error

    Contacto tiene un formulario con nombre, correo y mensaje. Antes de enviar, el código revisa que todo esté bien:

    validation.ts (resumido)
    if (values.name.trim().length < 2) errors.name = 'Escribe tu nombre.'
    • values.nameLo que la persona escribió en el campo "nombre".
    • .trim()Quita los espacios del principio y del final (así " " no cuenta como nombre).
    • .length < 2¿Tiene menos de 2 letras?
    • errors.name = '...'Si es así, guarda un mensaje de error que aparece debajo del campo.

    La página no tiene un servidor propio para enviar correos. Por eso, al enviar, abre el programa de correo de la persona con el mensaje ya escrito, usando un enlace mailto:.

    La página 404 aparece si alguien escribe una dirección que no existe. En lugar del aburrido "Not found", dice "Un eco perdido." con el mismo estilo del sitio y un botón para volver.

    CAPÍTULO 13

    La música de fondo

    Abajo a la derecha hay un pequeño reproductor: botón de play/pausa, unas barritas que bailan cuando suena y un control de volumen.

    • La canción se repite sola (audio.loop = true).
    • Cuando empieza o se pausa, el volumen sube o baja poco a poco (un fundido) para que no sea brusco.
    • El volumen que elijas se recuerda para la próxima visita, guardándolo en el navegador (localStorage, una pequeña libreta que cada página tiene en tu navegador).
    Qué salió mal (y una regla del navegador)

    Laura quería que la música sonara sola al entrar. Pero los navegadores no lo permiten: una página no puede hacer sonar audio hasta que la persona hace algo (un clic, tocar la pantalla, una tecla). Es una regla para que las páginas no te sorprendan con ruido.

    La solución: la página intenta sonar al cargar y, si el navegador lo bloquea, empieza con el primer clic en cualquier parte.

    Además encontramos un error raro: al hacer el fundido, a veces el volumen se calculaba como -0.0015 (¡negativo!) y el navegador fallaba. Lo arreglamos obligando a que el número siempre quede entre 0 y 1.

    PARTE 4

    El minijuego, desde cero

    Cómo se hace un juego de plataformas sin ningún motor de videojuegos: solo una hoja en blanco y matemáticas sencillas.

    CAPÍTULO 14

    Las reglas del juego

    Echo Collector ("recolector de ecos") es simple: hay 8 cristales brillantes flotando. Tienes que tocarlos todos lo más rápido posible.

    • Moverse: flechas ← → o las teclas A y D.
    • Saltar: barra espaciadora o W. Tres de los cristales están altos y hay que saltar.
    • En el celular: tocar el lado izquierdo o derecho para moverse y deslizar el dedo hacia arriba para saltar.

    El juego tiene tres estados, como un semáforo:

    EstadoQué pasa
    idle (en espera)La escena está quieta y el botón dice "Jugar".
    playing (jugando)El reloj corre y puedes moverte.
    finished (terminado)Muestra tu tiempo, guarda tu mejor marca y el botón dice "Jugar de nuevo".

    ¿Dónde se dibuja un juego en una página web?

    En un canvas (lienzo). Es una etiqueta HTML que es literalmente una hoja en blanco donde JavaScript puede pintar: rectángulos, círculos, imágenes. No hay botones ni textos ahí dentro: solo píxeles.

    En simple

    El resto de la página es como armar con piezas de Lego. El canvas es como un tablero de dibujo: tú decides qué pintar en cada punto.

    CAPÍTULO 15

    El bucle: como un libro animado

    ¿Alguna vez hiciste un dibujo en la esquina de un cuaderno y pasaste las hojas rápido para verlo moverse? Los videojuegos funcionan exactamente así.

    1
    2
    3
    4
    5
    6

    Cada "hoja" se llama frame (fotograma). El juego dibuja unos 60 frames por segundo. En cada uno hace siempre lo mismo, en este orden:

    1. Leer qué teclas estás pulsando.
    2. Mover todo un poquito (el personaje, los cristales, las partículas).
    3. Revisar si el personaje tocó un cristal.
    4. Borrar el lienzo y dibujar todo en su nueva posición.

    Y vuelve a empezar. A eso se le llama bucle de juego (game loop).

    Pruébalo · el bucle

    Frames dibujados: 0

    Baja los frames por segundo a 5 y verás la bola "a saltos", como un libro animado con pocas hojas. Con 60 parece movimiento continuo.

    El código del bucle

    engine/GameLoop.ts (simplificado)
    function tick(now) {
  const dt = (now - lastTime) / 1000   // segundos desde el frame anterior
  lastTime = now
  update(dt)                         // mover todo
  draw()                             // pintar todo
  requestAnimationFrame(tick)        // "llámame otra vez en el próximo frame"
}
    • requestAnimationFrame(tick)Le pedimos al navegador: "cuando vayas a pintar la pantalla otra vez, ejecuta tick". Así el bucle se repite unas 60 veces por segundo.
    • dtViene de delta time: cuánto tiempo pasó desde el frame anterior. Normalmente 0,016 segundos.
    Por qué importa el dt

    Hay pantallas que dibujan 60 veces por segundo y otras 144. Si el personaje avanzara "3 píxeles por frame", en la pantalla rápida correría más del doble de rápido. Si avanza "430 píxeles por segundo × dt", va igual de rápido en todas.

    CAPÍTULO 16

    Caminar, saltar y caer

    El personaje tiene una posición (dónde está) y una velocidad (hacia dónde y qué tan rápido va). En cada frame:

    engine/Player.ts (simplificado)
    vy += gravedad * dt          // la gravedad empuja hacia abajo
y  += vy * dt                // la velocidad cambia la posición

if (y >= suelo) {            // ¿atravesó el suelo?
  y = suelo                  //   lo ponemos encima
  vy = 0                     //   y se detiene
}

if (saltar && enElSuelo) vy = -fuerzaDeSalto   // salto = empujón hacia arriba
    • vyVelocidad vertical. En la pantalla, Y crece hacia abajo (al revés que en matemáticas del colegio). Por eso un número negativo significa "hacia arriba".
    • vy += gravedad * dtCada frame la velocidad hacia abajo aumenta un poco. Por eso, al saltar, subes cada vez más lento, te detienes y luego caes cada vez más rápido.
    • vy = -fuerzaDeSaltoSaltar es solo dar un empujón hacia arriba. La gravedad hace el resto: dibuja la curva sola.
    Pruébalo · gravedad y salto

    Altura máxima: 0 px

    Prueba gravedad baja: parece que estás en la Luna. Gravedad alta y poco salto: no llegarías a los cristales altos.

    Trucos para que se sienta bien

    Los juegos de plataformas usan pequeños trucos invisibles que hacen que el control se sienta "justo":

    • Tiempo coyote: puedes saltar hasta 0,08 segundos después de salir del borde. Se llama así por el Coyote de los dibujos animados, que corre en el aire antes de caer.
    • Memoria de salto: si pulsas saltar un instante antes de tocar el suelo, el juego lo recuerda y salta al aterrizar.
    • Aceleración: el personaje no pasa de quieto a correr de golpe; acelera rapidísimo, pero no instantáneamente.
    CAPÍTULO 17

    Tocar un cristal: cajas invisibles

    ¿Cómo sabe el juego que tocaste un cristal? Revisar cada píxel del dibujo sería lentísimo. El truco: imaginamos una caja invisible alrededor del personaje y otra alrededor de cada cristal. Si las cajas se tocan, hubo choque.

    Se llama colisión AABB (cajas alineadas a los ejes: sus lados siempre son horizontales y verticales).

    Pruébalo · arrastra la caja roja

    Dos cajas se tocan si se cumplen las cuatro condiciones a la vez:

    engine/Collision.ts
    function seTocan(a, b) {
  return a.x < b.x + b.ancho &&   // A empieza antes de que B termine
         a.x + a.ancho > b.x &&   // A termina después de que B empieza
         a.y < b.y + b.alto  &&   // lo mismo, pero en vertical
         a.y + a.alto  > b.y
}
    • &&Significa "y". Las cuatro condiciones tienen que ser verdad.
    • a.xDónde empieza la caja A por la izquierda. a.x + a.ancho es dónde termina por la derecha.
    En simple

    Si una caja está completamente a la izquierda, a la derecha, arriba o abajo de la otra, no se tocan. Si no está en ninguno de esos casos, se están tocando.

    Cuando el personaje toca un cristal: se marca como recogido, el marcador sube (ECOS 03 / 08), salen chispas y el cristal se desvanece.

    CAPÍTULO 18

    Cristales, chispas y récord

    Cristales que flotan

    Los cristales suben y bajan suavemente. Para eso usamos la función seno (Math.sin), que produce una ola: sube, baja, sube, baja, para siempre.

    engine/Echo.ts (simplificado)
    y = alturaBase + Math.sin(tiempo * velocidad) * 6
    • Math.sin(...)Da un número que va de -1 a 1 y vuelve, como una ola.
    • * 6Lo multiplicamos por 6 para que el cristal suba y baje 6 píxeles.

    Cada cristal empieza la ola en un momento distinto, así no flotan todos al mismo ritmo, como si fueran soldados.

    Las chispas (partículas)

    Al recoger un cristal salen 16 puntitos de luz en todas direcciones. Cada uno es una partícula: un objeto mínimo con posición, velocidad y "vida". Cada frame se mueve un poco, se frena y pierde vida. Cuando su vida llega a cero, desaparece.

    React y el juego: dos mundos separados

    Una decisión importante: el juego no sabe que existe React. Es código JavaScript puro que solo dibuja en el lienzo. React se encarga del resto de la página (el marcador, el botón).

    Se comunican con avisos (callbacks). El juego avisa "recogió un cristal", "pasó una décima de segundo" o "terminó", y React actualiza el marcador.

    Por qué no actualizar el marcador 60 veces por segundo

    Cada vez que React actualiza algo en la pantalla tiene trabajo extra. El reloj solo se actualiza 10 veces por segundo: el ojo no nota la diferencia y la página trabaja 6 veces menos.

    El récord

    Al terminar, el mejor tiempo se guarda en localStorage (la libreta del navegador). La próxima vez que juegues, lo recuerda. Siempre lo envolvemos en un try/catch ("intenta; si falla, no pasa nada") porque en algunos navegadores, como en modo incógnito, esa libreta puede no estar disponible.

    Detalles que casi nadie nota

    • El lienzo se dibuja en alta resolución en pantallas nítidas (como las de los celulares), para que no se vea borroso.
    • Si cambias de pestaña, el juego se pausa solo.
    • Las teclas solo funcionan cuando el juego está activo. Si estás escribiendo en el formulario de contacto, la barra espaciadora no hace saltar a nadie.
    PARTE 5

    Dar vida al personaje

    El personaje era una sola imagen quieta. Todo su movimiento (capa, piernas, brazos, polvo) lo creamos con código.

    CAPÍTULO 19

    El problema: una foto que tiene que moverse

    En los juegos normales, el personaje se anima como un dibujo animado: alguien dibuja 6 u 8 imágenes de cada movimiento (caminar, saltar…) y el juego las pasa rápido. Esas imágenes juntas se llaman hoja de sprites.

    Nosotros solo teníamos una imagen de la encapuchada. Así que hicimos que el código la deformara, la moviera y le dibujara partes nuevas. A eso se le llama animación procedural: el movimiento se calcula en lugar de dibujarse a mano.

    No salió bien a la primera. Lo fuimos mejorando con lo que decía quien lo probaba:

    1. v1El personaje rebota al correr, se inclina y se voltea según la dirección. "La capa se ve muy quieta."
    2. v2La capa ondea un poco. "Se sigue viendo muy estática."
    3. v3La capa ondea mucho más, rebota y tiene inercia. Aparece el polvo. "Al voltearse parece una hoja de papel."
    4. v4Nuevo giro: rápido, con frenada y polvo.
    5. v5Piernas nuevas que se mueven. "Las piernas no se mueven."
    6. v6El salto con impulso y polvo al caer.
    7. v7Movimiento en el aire. "En el aire parece un palo."
    8. v8Brazos que se mueven. "¿Y las manos?"
    Lección

    Ningún programador lo hace perfecto la primera vez. Se hace algo, se prueba, se escucha lo que falla y se mejora. Esto se llama iterar.

    CAPÍTULO 20

    Estirar, aplastar y rebotar

    Los animadores de dibujos animados tienen unos "principios" desde hace casi cien años. Usamos varios, solo cambiando el tamaño de la imagen:

    TrucoQué hace el personajePor qué funciona
    AplastarAl aterrizar se hace más bajito y más ancho un instante.Se siente el peso del golpe.
    EstirarAl despegar se hace más alto y delgado.Se siente la velocidad.
    AnticipaciónAntes de saltar se agacha 0,07 segundos.Igual que una persona real: para saltar primero doblas las rodillas.
    Rebote al correrSube y baja con cada paso.Al correr, el cuerpo no va en línea recta.
    InclinaciónSe inclina hacia delante al correr.Así corremos las personas.
    RespiraciónQuieta, crece y encoge muy poquito.Algo totalmente quieto parece muerto.
    engine/BodyPose.ts (idea simplificada)
    altoDelDibujo  = 1 - aplastado + estirado
anchoDelDibujo = 1 + aplastado - estirado
    • 1Tamaño normal (100 %).
    • - aplastadoAl aterrizar, aplastado vale por ejemplo 0,3: el dibujo queda al 70 % de alto. Luego ese número baja a 0 poco a poco y el personaje recupera su forma.
    • + aplastadoEn el ancho se suma: cuando algo se aplasta, se ensancha. Así parece hecho de algo blando y no de cartón.

    El giro: lo que salió mal

    Para que el personaje mire al otro lado, al principio lo hacíamos "adelgazar" hasta desaparecer y volver a aparecer al revés. Parecía una hoja de papel girando.

    La solución, que usan casi todos los juegos de plataformas: voltearlo de golpe en un solo frame (el ojo no lo nota) y tapar el cambio con movimiento: una frenada con un brinquito, la capa que da un latigazo y un poco de polvo, como si derrapara.

    CAPÍTULO 21

    La capa: resortes invisibles

    Paso 1: partir la imagen en trocitos

    Para que la capa ondee sin que se deforme la cara, partimos la imagen en una cuadrícula de 14 × 10 cuadritos, como un mosaico. Cada esquina del mosaico puede moverse un poco, y la imagen se estira entre ellas como una tela.

    Cada esquina tiene un peso que dice cuánto se mueve:

    • En la cara y el cuerpo: peso 0, no se mueve nada.
    • En la punta de abajo de la capa: peso máximo, se mueve mucho.
    • En el cuello: casi nada, porque la capa cuelga de los hombros.

    Paso 2: ¿cuánto se mueve? Un resorte

    Una tela de verdad no sigue al cuerpo al instante: se retrasa, se pasa de largo y rebota. Para imitarlo usamos un resorte matemático.

    En simple

    Imagina una bola atada a un elástico. Si mueves la mano, la bola la sigue con retraso, se pasa y rebota hasta calmarse. La rigidez es lo duro que es el elástico. La amortiguación es como meter la bola en miel: frena el rebote.

    Pruébalo · el resorte de la capa

    La línea punteada es a dónde quiere ir la capa (el objetivo). El punto es dónde está. Con poca miel rebota mucho; con mucha, llega despacio y sin rebotar. La capa usa poca miel, para que rebote al aterrizar.

    engine/Cape.ts — el resorte completo
    const aceleracion = rigidez * (objetivo - valor)
                  - amortiguacion * velocidad
velocidad += aceleracion * dt
valor     += velocidad * dt
    • rigidez * (objetivo - valor)Cuanto más lejos está del objetivo, más fuerte tira el elástico.
    • - amortiguacion * velocidadLa miel: cuanto más rápido se mueve, más lo frena.
    • velocidad += ... y valor += ...Las mismas dos líneas que usamos para la gravedad. ¡Todo el movimiento del juego sale de esta misma idea!

    La capa tiene dos resortes: uno para estirarse hacia atrás (al correr, y hacia delante al frenar, por inercia) y otro para subir o bajar (cuelga al subir, flota al caer, rebota al aterrizar). Además le sumamos una ola que siempre recorre la tela.

    CAPÍTULO 22

    Piernas y brazos de palitos

    Las piernas estaban pintadas dentro de la imagen, así que no se podían mover. La solución tuvo dos pasos:

    1. Esconder la parte de la imagen donde estaban las piernas (y un brazo), con un recorte. Para saber exactamente dónde estaban, leímos los píxeles de la imagen con código.
    2. Dibujar piernas nuevas encima, como un muñeco de palitos con bisagras: muslo, rodilla, espinilla y bota.

    Cada pierna se describe con solo dos ángulos: cuánto gira la cadera y cuánto se dobla la rodilla.

    Pruébalo · el ciclo de la carrera
    engine/Legs.ts (simplificado)
    const balanceo = Math.sin(fase) * zancada
piernaDelantera.cadera = balanceo
piernaTrasera.cadera   = -balanceo       // la otra, al revés
piernaDelantera.rodilla = -Math.max(0, Math.cos(fase)) * flexion
    • Math.sin(fase)Otra vez la ola: la pierna va adelante y atrás.
    • -balanceoLa otra pierna hace lo contrario. ¡Así se camina!
    • Math.max(0, Math.cos(fase))La rodilla solo se dobla cuando la pierna va hacia delante (cuando la levantas para dar el paso).

    Los brazos

    Igual que las piernas, pero con hombro, codo y mano. Al correr, cada brazo va al revés que su pierna, como cuando corres de verdad. Antes de saltar se van hacia atrás para tomar impulso; al subir van adelante; al caer se abren para mantener el equilibrio.

    En el aire

    "En el aire parece un palo" fue el comentario. El problema: cuando el personaje está en el punto más alto, casi no se mueve, y su velocidad es cero, así que todo lo que dependía de la velocidad se quedaba quieto. Lo arreglamos agregando movimiento que siempre está activo en el aire: las piernas pedalean, los brazos aletean, el cuerpo se balancea y la capa ondea a tope.

    Qué salió mal
    • Al saltar, el brazo pasaba por delante de la cara y la tapaba. Bajamos su ángulo.
    • Las piernas y mangas eran tan oscuras que desaparecían sobre el fondo negro. Les pusimos un borde un poquito más claro.

    El polvo

    Usa las mismas partículas que las chispas de los cristales, pero grises, más grandes y que suben flotando. Salen con cada paso, al girar, al despegar y, sobre todo, al aterrizar: cuanto más alta la caída, más polvo.

    Terminar bien

    CAPÍTULO 23

    Una página para todos

    La accesibilidad es hacer que la página sirva también para personas con alguna dificultad: que no ven, que no usan ratón, o a las que el movimiento les marea.

    • Lectores de pantalla: las personas ciegas usan un programa que lee la página en voz alta. Por eso cada imagen tiene una descripción (alt), y los adornos (rombos, destellos) están marcados para que el lector los salte.
    • El juego también se describe: el lienzo dice en voz alta cosas como "3 de 8 ecos recogidos".
    • Solo teclado: todo se puede usar con la tecla Tab, y siempre se ve en qué elemento estás.
    • Movimiento reducido: hay personas que en su sistema activan "reducir movimiento" porque las animaciones les marean. La página lo detecta y apaga los destellos, las olas de la capa y los cristales flotantes. El juego sigue funcionando.
    CAPÍTULO 24

    Comprobar que funciona

    Después de cada cambio usamos dos comandos:

    Terminal
    npm run build   # prepara la versión final y revisa los tipos
npm run lint    # revisa el código buscando errores y malas prácticas

    Si alguno muestra un error, no se sigue hasta arreglarlo.

    Pero que el código no tenga errores no significa que se vea bien. Así que hicimos un pequeño programa que abre Chrome sin ventana y:

    • Toma fotos de la página en tamaño computador y celular, para compararlas con el mockup.
    • Revisa que en el celular no haya que deslizar hacia los lados.
    • Juega una partida completa solo, pulsando teclas, hasta ver "Jugar de nuevo" y el récord guardado.
    • Hace fotos ampliadas del personaje en cada momento del salto para revisar la animación.
    Qué salió mal

    Una foto "de celular" parecía cortada a la derecha. ¿Un error? No: el Chrome sin ventana tiene un ancho mínimo. Medimos el ancho real de la página y confirmamos que todo cabía. Lección: antes de arreglar algo, comprueba que de verdad está roto.
